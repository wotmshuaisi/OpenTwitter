# Pluggable Storage Abstraction

## Goal

Local filesystem today, any S3-compatible provider (AWS S3, Cloudflare R2, MinIO, Backblaze B2, DigitalOcean Spaces) later — swapped via one env var, with **zero changes** to route/db code. Kept deliberately simple: plain functions on a plain object, not classes or interfaces, so a small model can implement and extend it without needing to understand OOP polymorphism.

## Shape (the "contract")

Every driver module exports the same four functions:

```js
// storage/local-disk.js
module.exports = {
  async put(storageKey, fileBuffer) { /* write to disk */ },
  async get(storageKey) { /* return a Buffer or Readable stream */ },
  url(storageKey) { /* return a URL string the browser can hit */ },
  async delete(storageKey) { /* remove file */ },
};
```

```js
// storage/s3-compatible.js  (written later, same shape)
module.exports = {
  async put(storageKey, fileBuffer) { /* PutObjectCommand */ },
  async get(storageKey) { /* GetObjectCommand, return stream */ },
  url(storageKey) { /* signed URL or public CDN URL */ },
  async delete(storageKey) { /* DeleteObjectCommand */ },
};
```

## Selecting the active driver — `storage/index.js`

```js
const driverName = process.env.STORAGE_DRIVER || 'local'; // 'local' | 's3'
const driver = driverName === 's3'
  ? require('./s3-compatible')
  : require('./local-disk');

module.exports = driver; // routes/jobs import { put, get, url, delete } from here, nothing else
```

**Route and job code only ever does `const storage = require('../storage'); storage.put(...)`.** No file in `routes/`, `db/`, or `jobs/` imports `fs` or an S3 SDK directly — that's the entire rule that keeps the swap painless.

## Local driver details

```js
// storage/local-disk.js
const fs = require('fs/promises');
const path = require('path');
const ROOT = path.join(__dirname, '..', 'media-storage');

module.exports = {
  async put(storageKey, fileBuffer) {
    const fullPath = path.join(ROOT, storageKey);
    await fs.mkdir(path.dirname(fullPath), { recursive: true });
    await fs.writeFile(fullPath, fileBuffer);
    return storageKey;
  },
  async get(storageKey) {
    return fs.readFile(path.join(ROOT, storageKey));
  },
  url(storageKey) {
    return `/media/${storageKey}`; // served by a dedicated Express route below
  },
  async delete(storageKey) {
    await fs.unlink(path.join(ROOT, storageKey)).catch(() => {});
  },
};
```

## Serving files locally

A single Express route handles both public and private media:

```js
// routes/media.js
app.get('/media/*', requireAuthIfPrivate, (req, res) => {
  const storageKey = req.params[0];
  storage.get(storageKey).then(buf => res.send(buf));
});
```

When the driver later becomes `s3-compatible`, `url()` returns a signed S3/R2 URL instead of `/media/...`, and templates keep working unchanged because they only ever call `media.url` (a value already resolved by the route handler and passed into the template) — **never** hardcode `/media/...` in a view.

## Storage keys ("logical keys")

Format: `{ownerType}/{ownerId}/{ulid-or-timestamp}.{ext}`, e.g. `posts/42/1699999999-abc.jpg`. Generated in `routes/posts.js` at upload time, stored in `media.storage_key`. Never derived from the original filename (avoids collisions and path-traversal risk).

## Env config

```
STORAGE_DRIVER=local          # or "s3"
# only needed when STORAGE_DRIVER=s3:
S3_ENDPOINT=
S3_BUCKET=
S3_ACCESS_KEY=
S3_SECRET_KEY=
S3_REGION=
```

## Migration path (later, non-blocking now)

1. Write `storage/s3-compatible.js` using `@aws-sdk/client-s3` (works against any S3-compatible endpoint via `S3_ENDPOINT`).
2. Set `STORAGE_DRIVER=s3` + the `S3_*` env vars.
3. Run a one-off script that loops existing `media` rows, `local.get()` → `s3.put()` for each — a ~20 line script using the same two driver modules directly, no app code touched.
4. Done — no route, template, or db file changes required.

## Testing

- In tests, set `STORAGE_DRIVER=local` pointed at a temp directory (`ROOT` overridable via `MEDIA_STORAGE_ROOT` env var for test isolation), so tests never need network/S3 access.
