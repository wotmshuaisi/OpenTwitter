# Implementation Phases — Task Checklist

Tasks are kept small (roughly "one file or one route" per task) since the implementation model is small — big multi-file tasks are more likely to go wrong. Mark `[x]` with a one-line note on completion.

## Phase 0 — Scaffolding
- [ ] `npm init`, install: `express`, `better-sqlite3`, `ejs`, `express-session`, `bcrypt`, `multer`, `sharp`, `fluent-ffmpeg`, `socket.io`, `dotenv`
- [ ] `db/connection.js` — open SQLite file, set WAL/foreign_keys/busy_timeout pragmas
- [ ] `db/schema.sql` — all `CREATE TABLE IF NOT EXISTS` statements, loaded on startup
- [ ] `app.js` — Express app, session middleware, static `public/`, mount route files (empty stubs OK for now)
- [ ] `server.js` — http server, attach socket.io, start `jobs/worker.js` poller
- [ ] `views/layout.ejs` + `public/css/base.css` + `public/css/theme.css` — base HTML shell, theme toggle (light/dark/system via a `data-theme` attribute + small inline script, no framework)
- [ ] Vendor `htmx.min.js` into `public/`, include in layout

## Phase 1 — Auth, Profiles, Follow System
- [ ] `db/users.js` — `createUser`, `findByUsername`, `findByEmail`, `findById`, `updateProfile`
- [ ] `routes/auth.js` — `/register`, `/login`, `/logout`, `middleware/currentUser.js`, `middleware/requireAuth.js`
- [ ] `views/auth/register.ejs`, `views/auth/login.ejs`
- [ ] `db/follows.js` — `follow`, `unfollow`, `isFollowing`, `countFollowers`, `countFollowing`, `listFollowers`, `listFollowing`
- [ ] `routes/follows.js` — htmx follow/unfollow toggle endpoint
- [ ] `routes/profiles.js` + `views/profiles/show.ejs`, `views/profiles/edit.ejs`, `views/profiles/followers.ejs`

## Phase 2 — Storage Abstraction & Media Pipeline
- [ ] `storage/local-disk.js`, `storage/index.js` (driver selector)
- [ ] `db/media.js` — `createMediaRow`, `attachToOwner`, `markStatus`, `getById`
- [ ] `routes/media.js` — serves `/media/*` via `storage.get()`
- [ ] `db/jobs.js` — `enqueueJob`, `claimPendingJobs`, `markJobDone`, `markJobFailed`
- [ ] `jobs/worker.js` — `setInterval` poller wired in `server.js`
- [ ] `media/images.js` (sharp resize/thumbnail) + `jobs/handlers/generateThumbnail.js`
- [ ] `media/video.js` (fluent-ffmpeg thumbnail/transcode) + `jobs/handlers/transcodeVideo.js`
- [ ] Socket.io `media:ready` emit from job handlers, minimal client listener in `layout.ejs`

## Phase 3 — Posts, Mentions, Reposts, Sharing
- [ ] `db/posts.js` — `createPost`, `getById`, `getTimelineForUser`, `getPostsByUser`, keep `posts_fts` in sync in the same functions
- [ ] `routes/posts.js` — `POST /posts` (composer, multer upload), `GET /posts/:id`
- [ ] `views/partials/post-card.ejs` (the reusable fragment returned both by full pages and htmx endpoints)
- [ ] `db/mentions.js` — mention parsing + insert, `routes/posts.js` wires it into `createPost`
- [ ] `POST /posts/:id/repost` (toggle repost/unrepost) + quote-post composer variant
- [ ] Copy-link button (inline JS, clipboard API) in `post-card.ejs`

## Phase 4 — Feed, Timeline, Search
- [ ] `routes/feed.js` — `GET /` home timeline (following-based, paginated with `LIMIT`/`OFFSET` or keyset pagination)
- [ ] `views/feed/index.ejs`, infinite-scroll via `hx-get` + `hx-trigger="revealed"` on a sentinel element (no client JS beyond htmx attributes)
- [ ] `GET /search` — query `posts_fts` and `users_fts`, render combined results
- [ ] Empty-state templates for no-posts/no-results

## Phase 5 — Direct Messaging
- [ ] `db/conversations.js`, `db/messages.js`
- [ ] `routes/messages.js` — conversation list, thread view, `POST` send message
- [ ] Socket.io: join `user:{id}` room on connect, emit `message:new` to recipient's room, client listener does `hx-get` refresh of the thread pane
- [ ] Unread badge: compare `last_read_message_id` vs latest message id per conversation

## Phase 6 — Analytics & Statistics
- [ ] `db/analytics.js` — `recordEvent`, `rollupDay`, `getRollupsForSubject`
- [ ] Inline `recordEvent` calls on post view / profile view routes
- [ ] `jobs/handlers/rollupAnalytics.js` — hourly `setInterval` aggregation
- [ ] `routes/analytics.js` + `views/analytics/dashboard.ejs` — simple `<canvas>` or plain SVG bar/line rendering, no charting library

## Phase 7 — UI Polish Pass (lightweight)
- [ ] Consistent spacing/typography scale in `base.css` (plain CSS custom properties, no build step)
- [ ] Verify theme toggle is instant and flash-free (test the `data-theme` attribute approach on first paint — inline script in `<head>` before CSS loads, to avoid flash of wrong theme)
- [ ] Simple CSS transitions on hover/press states (no JS animation libraries)
- [ ] Mobile responsive pass with plain CSS flexbox/grid + media queries

## Phase 8 — Performance, Accessibility, QA, Deployment Prep
- [ ] Verify sub-1.5s page loads (no bundler means this should already be close — confirm with browser devtools network tab)
- [ ] Keyboard navigation + `aria-label`s on icon-only buttons (follow, repost, share)
- [ ] `prefers-reduced-motion` respected in `theme.css`
- [ ] SQLite backup: simple scheduled copy of the `.sqlite` file (or `VACUUM INTO`) to a backup path
- [ ] Deployment: single Node process (Express + Socket.io + job poller together) behind a reverse proxy (nginx/Caddy); document the two required volumes — the SQLite file and `media-storage/`
