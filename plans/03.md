# Database Schema (SQLite)

All statements live in `db/schema.sql`, run once at startup (`CREATE TABLE IF NOT EXISTS ...`) — no migration framework, just idempotent SQL. This is the simplest possible approach for a small implementation model: one file, top to bottom, no migration ordering/versioning system to reason about.

Startup pragmas (`db/connection.js`):
```js
db.pragma('journal_mode = WAL');
db.pragma('foreign_keys = ON');
db.pragma('busy_timeout = 5000');
```

## Tables

```sql
CREATE TABLE IF NOT EXISTS users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT NOT NULL UNIQUE,
  email TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  display_name TEXT NOT NULL,
  bio TEXT,
  avatar_media_id INTEGER REFERENCES media(id),
  header_media_id INTEGER REFERENCES media(id),
  location TEXT,
  website TEXT,
  theme_preference TEXT NOT NULL DEFAULT 'system', -- light | dark | system
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS sessions (
  id TEXT PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  data TEXT NOT NULL,
  expires_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS follows (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  follower_id INTEGER NOT NULL REFERENCES users(id),
  following_id INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(follower_id, following_id)
);
CREATE INDEX IF NOT EXISTS idx_follows_following ON follows(following_id);

CREATE TABLE IF NOT EXISTS media (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_type TEXT NOT NULL,      -- 'post' | 'user_avatar' | 'user_header' | 'message'
  owner_id INTEGER,               -- nullable until attached
  storage_key TEXT NOT NULL,       -- logical key, e.g. posts/42/abc123.jpg
  type TEXT NOT NULL,               -- image | video
  mime_type TEXT NOT NULL,
  thumbnail_key TEXT,
  status TEXT NOT NULL DEFAULT 'pending', -- pending | processing | ready | failed
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS posts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL REFERENCES users(id),
  body TEXT,
  type TEXT NOT NULL DEFAULT 'post', -- post | repost | quote
  repost_of_id INTEGER REFERENCES posts(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  deleted_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_posts_user_created ON posts(user_id, created_at);
CREATE INDEX IF NOT EXISTS idx_posts_repost_of ON posts(repost_of_id);

CREATE TABLE IF NOT EXISTS mentions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id INTEGER NOT NULL REFERENCES posts(id),
  mentioned_user_id INTEGER NOT NULL REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(post_id, mentioned_user_id)
);

CREATE TABLE IF NOT EXISTS conversations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS conversation_participants (
  conversation_id INTEGER NOT NULL REFERENCES conversations(id),
  user_id INTEGER NOT NULL REFERENCES users(id),
  last_read_message_id INTEGER,
  PRIMARY KEY (conversation_id, user_id)
);

CREATE TABLE IF NOT EXISTS messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL REFERENCES conversations(id),
  sender_id INTEGER NOT NULL REFERENCES users(id),
  body TEXT,
  media_id INTEGER REFERENCES media(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_messages_conversation ON messages(conversation_id, created_at);

CREATE TABLE IF NOT EXISTS analytics_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  event_type TEXT NOT NULL,        -- post_view | profile_view | follow
  subject_type TEXT NOT NULL,       -- post | user
  subject_id INTEGER NOT NULL,
  actor_id INTEGER REFERENCES users(id),
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE IF NOT EXISTS analytics_daily_rollups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  subject_type TEXT NOT NULL,
  subject_id INTEGER NOT NULL,
  metric TEXT NOT NULL,
  date TEXT NOT NULL,
  count INTEGER NOT NULL DEFAULT 0,
  UNIQUE(subject_type, subject_id, metric, date)
);

CREATE TABLE IF NOT EXISTS jobs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  type TEXT NOT NULL,
  payload TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',
  attempts INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- Full text search (posts and users)
CREATE VIRTUAL TABLE IF NOT EXISTS posts_fts USING fts5(body, content='posts', content_rowid='id');
CREATE VIRTUAL TABLE IF NOT EXISTS users_fts USING fts5(username, display_name, bio, content='users', content_rowid='id');
```

## Keeping FTS tables in sync

Rather than SQLite triggers (harder for a small model to debug), keep it explicit: every `db/posts.js -> createPost()` / `updatePost()` / `deletePost()` function also runs the matching `INSERT/UPDATE/DELETE INTO posts_fts` statement in the same function, inside one `db.transaction()`. Same pattern for `users_fts` in `db/users.js`. This keeps "what updates search" visible in the same file as "what updates the row," instead of hidden in a trigger.

## Notes

- No `likes` table yet — the feature list doesn't request likes/favorites. Flagged in `04-feature-specs.md` for confirmation before adding.
- `owner_id` on `media` is nullable so a file can be uploaded, get a `media` row, and be linked to its `post`/`message`/`user` row in a second step within the same request — avoids needing the post ID before the file exists.
